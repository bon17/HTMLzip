# HTML 슬라이드 제작 원칙

이 저장소의 모든 슬라이드(덱)는 이 문서를 따른다.
목표는 한 문장이다.

> **HTML 파일 하나만 열면, 학생의 눈을 붙잡는 움직이는 슬라이드와 발표·필기·편집 도구가 전부 들어 있다.**

기능 등급은 세 가지로 나눈다.

- **[필수]** 모든 덱에 반드시 들어간다.
- **[권장]** 특별한 이유가 없으면 넣는다.
- **[선택]** 필요할 때만 넣는다.

---

## 1. 핵심 원칙

1. **단일 파일**: 덱 하나는 HTML 파일 하나다. 빌드 과정 없이 더블클릭으로 열리고, 인터넷이 끊겨도 동작한다.
2. **모션으로 흥미와 집중을**: 전환, 등장, 강조, 상호작용, 보상 모션을 다양하게 써서 학생의 흥미를 끌고 집중을 이어 간다. 모션은 내용 이해를 돕는 방향으로만 쓰고, 강도를 조절하거나 끌 수 있어야 한다. (§4)
3. **도구 내장**: 펜, 형광펜, 레이저, 칠판, 타이머 같은 발표 도구가 모든 덱에 들어간다. (§3)
4. **무엇이든 편집**: 텍스트뿐 아니라 이미지, 도형, 위치, 크기, 스타일, 모션, 슬라이드 순서까지 브라우저에서 바로 바꾸고 저장한다. (§3.6–3.8)
5. **전체 화면은 슬라이드 중심**: 전체 화면으로 바꾸면 도구가 모두 사라지고 슬라이드와 페이지 표시만 보인다. 필통과 메뉴는 필요할 때 화면 가장자리에서 잠깐 불러온다. (§3.5)
6. **기능은 공통, 디자인은 자유**: 기능 코드(엔진)는 모든 덱이 같은 것을 쓰고, 디자인은 덱마다 자유롭게 만든다. 엔진은 디자인을 정하지 않는다. (§5, §6)
7. **기록 보존**: 필기, 설정, 편집 내용은 브라우저에 자동 저장되고 되돌리기가 가능하다.
8. **어디서나 동작**: 노트북, 대형 화면, 태블릿(터치·펜)에서 모두 동작한다. 창 크기가 바뀌어도 레이아웃과 필기 위치가 어긋나지 않는다.

## 2. 화면 구성 (일반 화면)

늘 보이는 도구는 **메뉴 버튼, 필통, 페이지 꼬리표** 세 가지뿐이다. 나머지 기능은 모두 메뉴 서랍 안에 둔다. 슬라이드를 최대한 가리지 않기 위해서다.

| 영역 | 내용 | 등급 |
|---|---|---|
| 무대(stage) | 1920×1080 고정 좌표계. 화면에 맞춰 비율을 유지한 채 확대·축소한다(남는 공간은 여백). | 필수 |
| 필통 | 필기 도구(손·펜·형광펜·지우개·레이저·색·되돌리기)만 담은 작은 캡슐. 기본 위치는 왼쪽 아래다. | 필수 |
| 메뉴 버튼 | 왼쪽 위의 작은 버튼. 누르면 메뉴 서랍이 열린다. 점검할 문제가 있으면 작은 점이 붙는다. | 필수 |
| 메뉴 서랍 | 왼쪽에서 나오는 넓은 서랍. ‘메뉴’ 탭과 ‘슬라이드’ 탭(썸네일 목록, §3.7)이 있다. 서랍 밖을 누르거나 `Esc`를 누르면 닫히고, 이때는 슬라이드가 넘어가지 않는다. | 필수 |
| 넘김 화살표 | 화면 양옆 가운데의 큰 반투명 화살표. 마우스를 움직이면 나타나고 2초 뒤 사라진다. 터치 기기에서는 흐리게 늘 보인다. | 권장 |
| 페이지 꼬리표 | 슬라이드 오른쪽 아래의 작은 꼬리표. `현재 / 전체`(예: `4 / 9`)와 그 아래 얇은 진행 선을 보여 준다. | 필수 |

**필통**

- **옮기기**: 손잡이(점 여섯 개)를 끌어 화면 어디에나 둔다.
- **방향**: 손잡이를 두 번 누르면 가로와 세로가 바뀐다.
- **접기**: 필통 끝의 접기 버튼을 누르면 지금 도구 아이콘이 든 동그란 버튼 하나로 줄어든다. 누르면 다시 펼쳐진다.
- **기억**: 위치, 방향, 접힘 상태는 다음에 열 때도 그대로다.
- **모양**: 버튼은 아이콘만 보여 주고 이름은 마우스를 올리면 나온다. 지금 쓰는 도구는 강조색으로 칠한다.

**메뉴 서랍의 ‘메뉴’ 탭**

기능을 큰 타일(아이콘 + 한글 이름)로 묶어 보여 준다.

`수업: 목차 · 칠판 · 가리기 · 타이머 · 뽑기 · 축하 · 발표자 보기 · 발표자 창 · 전체 화면 │ 필기: 이 장 지우기 · 전체 지우기 · 다시 하기 │ 만들기: 편집 · 점검 · 설정 · 단축키`

켜고 끄는 기능(칠판, 타이머, 발표자 보기, 전체 화면, 편집)은 켜져 있으면 타일을 진하게 칠한다. ‘점검’ 타일은 문제 개수를 함께 보여 준다(예: `점검 3`).

전체 화면에서는 페이지 꼬리표만 남고 이 표의 나머지 UI는 모두 숨는다(§3.5).

## 3. 기능 명세

모든 기능은 **버튼으로도, 단축키로도** 쓸 수 있어야 한다. 단축키는 모든 덱에서 같게 유지한다.

### 3.1 이동

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 이전 / 다음 | 남은 단계(§4.2 `data-step`)가 있으면 단계를 먼저 진행하고, 없으면 슬라이드를 넘긴다. | `←` `→` / `Space` / `PageUp` `PageDown` | 필수 |
| 처음 / 끝 | 첫 슬라이드, 마지막 슬라이드로 이동 | `Home` / `End` | 필수 |
| 번호로 이동 | 숫자를 입력한 뒤 Enter | 숫자 + `Enter` | 권장 |
| 목차 | 슬라이드 제목 목록. 클릭하면 이동한다. | `O` | 필수 |
| 클릭으로 넘기기 | 손 도구일 때 화면을 클릭하면 다음으로 간다. 상호작용 요소(§4.3)를 클릭하면 넘어가지 않고 그 요소만 반응한다. | — | 필수 |
| 스와이프 | 터치 화면에서 좌우로 밀어 넘긴다. 손 도구일 때만 동작한다. | — | 필수 |
| 주소 유지 | `#5`처럼 주소로 특정 슬라이드를 연다. 새로고침해도 위치가 유지된다. | — | 필수 |
| 숨긴 슬라이드 건너뛰기 | 숨김 처리한 슬라이드(§3.7)는 발표 중 이동할 때 건너뛴다. | — | 필수 |

### 3.2 필기 도구

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 손 | 기본 상태. 클릭으로 넘기기와 링크·상호작용 요소 클릭이 가능하다. | `V` 또는 `Esc` | 필수 |
| 펜 | 자유 곡선. 선을 부드럽게 보정하고, 가능한 기기에서는 펜 압력을 반영한다. | `P` | 필수 |
| 형광펜 | 반투명한 굵은 선. 글자 위에 칠해도 글자가 보인다. | `H` | 필수 |
| 지우개 | 두 가지 방식이 있다. **획 지우개**는 닿은 획을 통째로 지우고, **부분 지우개**는 문지른 부분만 지운다. 지우개가 선택된 상태에서 `E`나 지우개 버튼을 다시 누르면 방식이 바뀐다. 지우개 크기는 3단계다. | `E` | 필수 |
| 레이저 | 빨간 점과, 잠깐 남았다 사라지는 꼬리 | `L` | 필수 |
| 색 | 프리셋 6색과 굵기 3단계 | `C` (색 순환) | 필수 |
| 되돌리기 | 필기, 지우개, 이 장 지우기, 전체 지우기를 모두 되돌릴 수 있다. | `Ctrl/⌘ + Z` | 필수 |
| 다시 하기 | 되돌린 작업을 다시 적용한다. | `Ctrl/⌘ + Shift + Z` | 권장 |
| 이 장 지우기 | 현재 슬라이드(또는 칠판)의 필기를 전부 지운다. 되돌리기로 복구할 수 있다. | `X` | 필수 |
| 전체 지우기 | 모든 슬라이드와 칠판의 필기를 한 번에 지운다. 실수로 누르지 않도록 확인 창을 띄우고, 지운 뒤에도 되돌리기로 복구할 수 있다. | `Shift + X` | 필수 |

필기 규칙은 다음과 같다.

- 필기는 슬라이드마다 따로 저장한다. 다른 슬라이드에 갔다가 돌아와도 남아 있다.
- 필기는 슬라이드 순서 번호가 아니라 **슬라이드 고유 id(`data-id`)** 에 묶는다. 슬라이드 순서를 바꿔도 필기가 따라간다.
- 좌표는 **무대 좌표(1920×1080) 기준**으로 저장한다. 그래서 창 크기를 바꾸거나 전체 화면으로 전환해도 위치가 그대로다.
- 입력은 Pointer Events 하나로 마우스, 터치, 펜을 모두 처리한다. 필기 도구 사용 중에는 스크롤과 스와이프를 막는다.
- 필기 도구를 쓰는 중에도 키보드 이동(이전/다음)은 동작한다.
- 레이어 순서는 아래부터 `슬라이드 내용 → 필기 캔버스 → 레이저 → 필통·메뉴·패널`이다.

### 3.3 모드

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 슬라이드 | 기본 발표 화면 | `B` (칠판과 전환) | 필수 |
| 칠판 | 빈 판서 화면. 여러 장을 추가할 수 있다. 슬라이드 모드로 돌아오면 보던 슬라이드로 복귀한다. | `B` | 필수 |
| 보기 모드 | `기본` 또는 `발표자`. 발표자 보기는 현재 슬라이드, 다음 슬라이드 미리보기, 발표자 노트, 타이머를 한 화면에 보여 준다. | — | 권장 |

### 3.4 발표 보조

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 타이머 | 경과 시간과 카운트다운을 전환한다. 시작, 일시정지, 초기화를 지원한다. | `T` | 필수 |
| 축하 효과 | 색종이(confetti)를 터뜨린다. 학생이 정답을 맞혔을 때 바로 쓴다. | `G` | 필수 |
| 필통 옮기기·방향 | 손잡이를 끌어 옮기고, 두 번 누르면 가로·세로가 바뀐다. 설정에서 처음 위치로 되돌릴 수 있다. | — | 권장 |
| 필통 접기 | 동그란 버튼 하나로 줄였다가 다시 펼친다(§2). | — | 필수 |
| 단축키 도움말 | 단축키 목록을 화면 위에 띄운다. | `?` | 필수 |
| 랜덤 뽑기 | 목록(한 줄에 하나)에서 하나를 뽑는다. 항목이 빠르게 바뀌다가 점점 느려지며 멈춘다. 목록을 바로 고칠 수 있고, 덱이 정해 둔 목록 묶음(예: `1~5반`, `번호 1~30`)을 골라 쓸 수 있다. 뽑힌 항목 빼기, 최근 기록을 지원한다. `Space`·`Enter`로 다시 뽑는다. | `R` | 권장 |
| 화면 가리기 | 검은 화면 또는 흰 화면으로 잠깐 가려 학생의 눈을 발표자에게 모은다. 같은 키를 다시 누르면 돌아온다. | `.` / `,` | 권장 |
| 효과음 | 타이머 종료와 랜덤 뽑기에만 짧은 소리를 낸다. 켜고 끌 수 있다(§4.5). | `M` | 권장 |
| 발표자 창 | 새 창에 발표자 화면(현재·다음 슬라이드, 단계, 노트, 타이머)을 연다. 두 창은 같은 슬라이드와 단계를 따라가고, 어느 창에서 넘겨도 된다. 같은 컴퓨터 안의 두 창끼리만 연결되며 인터넷이나 서버가 필요 없다. 팝업이 막히면 허용 방법을 알려 준다. | `S` | 권장 |

발표 중 `R`은 랜덤 뽑기다. 편집 모드의 `R`(모션 미리보기, §3.6)과 겹치지 않는다. 덱이 쓸 목록 묶음은 `<main id="deck">` 안에 `<script type="application/json" class="hz-picker">{"1~5반": ["1반", "2반"]}</script>`처럼 둔다.

### 3.5 전체 화면 (슬라이드 중심 보기)

전체 화면(메뉴 서랍의 ‘전체 화면’ 또는 `F`)으로 바꾸면 **슬라이드와 페이지 꼬리표만** 보인다. 필통과 메뉴 버튼은 필요할 때 화면 가장자리에서 잠깐 불러온다.

| 규칙 | 등급 |
|---|---|
| 브라우저 전체 화면으로 전환하고, 필통·메뉴 버튼·메뉴 서랍·넘김 화살표를 모두 숨긴다. **페이지 꼬리표만 남긴다.** | 필수 |
| 페이지 꼬리표는 오른쪽 아래에 작고 흐리게 보여서 내용을 가리지 않는다. | 필수 |
| 이동(키보드, 클릭, 스와이프, 발표용 리모컨)은 그대로 동작한다. | 필수 |
| 필기·칠판·타이머·랜덤 뽑기·화면 가리기·축하 효과 단축키도 그대로 동작한다. 도구를 바꾸면 화면 구석에 작은 알림이 1초 동안 떴다가 사라진다. | 필수 |
| 마우스가 2초 동안 멈추면 커서를 숨긴다. 펜·레이저를 쓸 때는 커서 대신 도구 모양을 보여 준다. | 필수 |
| `F`를 다시 누르거나 `Esc`를 누르면 원래 화면으로 돌아오고 UI가 다시 나타난다. 전체 화면에서 손 도구로 돌아갈 때는 `V`를 쓴다(`Esc`는 전체 화면을 끝낸다). | 필수 |
| 브라우저가 전체 화면을 허용하지 않는 환경(일부 아이폰 사파리, 다른 페이지 안에 삽입된 경우 등)에서도 UI 숨김은 똑같이 동작하고, 슬라이드가 창을 꽉 채운다. | 필수 |
| **필통·메뉴 잠깐 불러오기**: 화면 가장자리(위·아래·왼쪽·오른쪽 어디든)에 마우스를 가져가면 필통과 메뉴 버튼이 나타난다. 여기서 도구를 바꾸거나 메뉴를 열 수 있고, 마우스가 벗어나 1초가 지나면 다시 숨는다. 펜으로 그리는 중(누른 상태)에는 가장자리에 닿아도 불러오지 않는다. | 필수 |
| 터치 기기에서는 화면 가장자리를 탭하면 필통과 메뉴 버튼이 나타난다. 이 탭으로는 다음 슬라이드로 넘어가지 않는다. 3초 동안 조작이 없으면 다시 숨는다. | 필수 |

### 3.6 편집: 요소

편집 모드(`Shift + E`)를 켜면 슬라이드의 **모든 요소**를 편집할 수 있다. 편집 모드에서는 발표용 한 글자 단축키(P, H, E 등)가 꺼지고 아래 편집 단축키가 동작한다.

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 편집 모드 | 켜고 끈다. 편집 중에는 화면 위쪽에 편집 도구 막대, 오른쪽에 속성 패널이 나타나고, 메뉴 서랍이 ‘슬라이드’ 탭으로 열린 채 고정된다. 필통은 숨는다. | `Shift + E` (끄기: `Esc`) | 필수 |
| 선택 | 클릭하면 선택된다(선택 테두리와 조절 핸들 표시). Shift+클릭이나 드래그 박스로 여러 개를 선택한다. `Tab`으로 다음 요소로 넘어간다. | `Tab` | 필수 |
| 이동 | 드래그로 옮긴다. 화살표는 1px, Shift+화살표는 10px씩 옮긴다. | 화살표 | 필수 |
| 정렬 가이드 | 드래그할 때 다른 요소의 가장자리·중앙, 무대 중앙에 맞춰지고 안내선이 보인다. | — | 권장 |
| 크기 조절 | 모서리·변 핸들로 조절한다. Shift를 누르면 비율을 유지한다. | — | 필수 |
| 회전 | 회전 핸들로 돌린다. Shift를 누르면 15° 단위로 돈다. | — | 권장 |
| 텍스트 수정 | 더블클릭하면 글자를 고칠 수 있다. 굵게, 기울임, 글자색, 글자 크기를 바꾼다. | `Ctrl/⌘ + B` / `I` | 필수 |
| 스타일 | 속성 패널에서 글자 크기·색, 배경색, 테두리, 모서리 둥글기, 투명도, 그림자를 바꾼다. | — | 필수 |
| 요소 추가 | 텍스트 상자, 도형(사각형·원·화살표·선), 이미지(파일 선택·붙여넣기·드래그). 이미지는 파일 안에 내장된다. | `Ctrl/⌘ + V` (이미지) | 필수 |
| 이모지·아이콘 추가 | 목록에서 골라 넣는다. | — | 권장 |
| 복사·붙여넣기·복제·삭제 | 다른 슬라이드에 붙여넣기도 된다. | `Ctrl/⌘ + C` / `V` / `D`, `Delete` | 필수 |
| 레이어 순서 | 맨 앞으로, 앞으로, 뒤로, 맨 뒤로 | `Ctrl/⌘ + ]` / `[` | 필수 |
| 정렬·배분 | 여러 요소를 왼쪽·가운데·오른쪽·위·아래로 맞추고 간격을 균등하게 한다. | — | 권장 |
| 그룹 | 여러 요소를 하나로 묶는다. | `Ctrl/⌘ + G` | 선택 |
| 모션 지정 | 선택한 요소의 등장·강조·퇴장 효과, 지연, 시간, 단계 번호, 상호작용(§4.3)을 고른다. 고르는 즉시 그 요소에서 미리보기가 재생된다. | — | 필수 |
| 모션 미리보기 | 현재 슬라이드의 모션을 처음부터 다시 재생한다. | `R` | 필수 |
| 되돌리기 | 편집 작업도 모두 되돌리기·다시 하기가 된다. 편집 모드에서는 편집을, 발표 중에는 필기를 되돌린다. | `Ctrl/⌘ + Z` / `Shift + Z` | 필수 |

글자를 입력하는 중에는 `Esc`(입력 끝내기)와 `Ctrl/⌘ + S`(저장)만 엔진이 가로채고, 나머지 키는 모두 글자 입력으로 쓴다.

### 3.7 편집: 슬라이드 관리

메뉴 서랍의 ‘슬라이드’ 탭(썸네일 목록)에서 한다.

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 순서 변경 | 썸네일을 드래그해서 옮긴다. 키보드로는 선택한 슬라이드를 한 칸씩 옮긴다. | `Alt + ↑` / `Alt + ↓` | 필수 |
| 추가 | 현재 슬라이드 뒤에 새 슬라이드를 넣는다. | — | 필수 |
| 레이아웃으로 추가 | 덱 디자인에 등록된 레이아웃(§5.2) 중에서 골라 추가한다. 등록된 레이아웃이 없으면 빈 슬라이드를 추가한다. | — | 권장 |
| 복제·삭제 | 현재 슬라이드를 복제하거나 삭제한다. 삭제는 되돌리기로 복구할 수 있다. | — | 필수 |
| 숨기기 | 발표 때는 건너뛰지만 파일에는 남긴다. 썸네일에 흐리게 표시한다. | — | 권장 |
| 여러 장 선택 | Shift/Ctrl+클릭으로 여러 장을 골라 한꺼번에 옮기거나 삭제한다. | — | 권장 |
| 슬라이드 설정 | 제목, 배경(색·그라디언트·이미지), 전환 효과, 배경 움직임(§4.3), 발표자 노트를 바꾼다. | — | 필수 |

### 3.8 편집: 저장과 점검

| 기능 | 동작 | 단축키 | 등급 |
|---|---|---|---|
| 저장 | 수정 내용을 반영한 HTML을 저장한다. 크롬·엣지는 File System Access API로 파일에 직접 저장하고, 그 외 브라우저는 새 파일로 다운로드한다. | `Ctrl/⌘ + S` | 필수 |
| 자동 임시 저장 | 편집 내용을 브라우저에 임시 저장한다. 다시 열면 복구할지 묻는다. | — | 필수 |
| 점검 | 덱을 자동 검사하고 문제 개수를 배지로 보여 준다(예: `점검 6`). 클릭하면 문제 목록이 나오고, 항목을 누르면 해당 슬라이드의 해당 요소로 이동한다. | — | 필수 |

**점검** 항목은 다음과 같다.

- 글자가 무대 밖이나 상자 밖으로 넘침
- 요소가 무대 밖으로 벗어남
- 빈 슬라이드
- 제목(`data-title`) 없는 슬라이드
- 깨진 이미지
- 대체 텍스트(`alt`) 없는 이미지
- 알 수 없는 모션 이름
- 아직 넣지 않은 그림(`data-placeholder` 자리표시, §6.3)
- 모션 연출 규칙(§4.4) 위반: 같은 등장 효과가 3장 넘게 연속됨, 한 화면에 동시에 움직이는 요소가 너무 많음

일부러 무대 밖에 걸쳐 둔 장식처럼 의도한 예외는 요소에 `data-check-ignore`를 붙이면 점검에서 빠진다.

저장한 파일에는 편집용 표시(선택 테두리, 핸들, 엔진이 붙인 상태 클래스)가 남지 않아야 한다.

### 3.9 설정

설정은 덱별로 브라우저에 저장한다.

| 항목 | 등급 |
|---|---|
| 모션 강도: `끄기` / `차분` / `기본` / `화려` (§4.5) | 필수 |
| 라이트·다크 전환 (덱 디자인이 둘 다 제공할 때, §5.2) | 권장 |
| 강조색, 모션 속도, 필기 기본 색·굵기, 필통 방향·처음 위치로, 넘김 화살표 보이기, 타이머 기본값, 전체 화면에서 페이지 꼬리표 표시 여부, 효과음 켜기·끄기 | 권장 |

## 4. 모션 그래픽

### 4.1 목적: 흥미와 집중

모션은 꾸밈이 아니라 **수업 도구**다. 모든 모션은 아래 넷 중 하나를 위해 쓴다.

- **시선 안내**: 지금 볼 곳으로 눈을 데려간다. (등장, 강조)
- **이해 돕기**: 순서, 변화, 관계를 움직임으로 보여 준다. (단계 등장, 모프, 도식)
- **참여 유도**: 학생이 예측하고 답하게 만든다. (상호작용)
- **분위기와 보상**: 지루함을 깨고 성취감을 준다. (전환, 배경, 축하)

### 4.2 작성 방식: 선언형

모션은 JS를 직접 쓰지 않고 **HTML 속성으로 선언**한다. 편집 모드의 모션 지정(§3.6)도 이 속성을 읽고 쓴다.

```html
<section class="slide" data-id="s-todo" data-title="오늘 할 일"
         data-transition="push" data-ambient="drift">
  <h2 style="left:160px; top:120px; width:1600px"
      data-anim="split-words">오늘 할 일</h2>

  <ul style="left:160px; top:320px; width:960px">
    <li data-anim="fade-up" data-step="1">웹앱 계획 세우기</li>
    <li data-anim="fade-up" data-step="2"
        data-emphasis="highlight" data-emphasis-step="3">첫 화면 만들기</li>
  </ul>

  <div class="flip-card" style="left:1220px; top:320px; width:540px; height:340px"
       data-anim="pop" data-step="4" data-interact="flip">
    <div class="front">Q. 첫 화면에 꼭 있어야 하는 것은?</div>
    <div class="back">사용자가 할 일 딱 한 가지!</div>
  </div>

  <aside class="notes">발표자 노트: 카드는 학생에게 먼저 답을 물어보고 뒤집기</aside>
</section>
```

| 속성 | 위치 | 뜻 |
|---|---|---|
| `data-id` | 슬라이드 | 슬라이드 고유 id. 필기, 숨김 상태 등이 여기에 묶인다. 한 번 정하면 바꾸지 않는다. |
| `data-title` | 슬라이드 | 목차, 썸네일, 점검에 쓰이는 제목 |
| `data-transition` | 슬라이드 | 전환 효과. 생략하면 덱 기본값을 쓴다. |
| `data-ambient` | 슬라이드·요소 | 배경 움직임 |
| `data-celebrate` | 슬라이드 | 슬라이드에 들어오면 보상 효과를 재생한다(예: 마지막 슬라이드). |
| `data-anim` | 요소 | 등장 효과 |
| `data-emphasis` / `data-emphasis-step` | 요소 | 강조 효과와 그 단계. 단계를 생략하면 등장 직후 한 번 재생한다. |
| `data-exit` / `data-exit-step` | 요소 | 퇴장 효과와 그 단계 |
| `data-step` | 요소 | "다음"을 누를 때마다 번호 순서대로 등장한다. 없으면 슬라이드에 들어올 때 자동 재생된다. |
| `data-delay` / `data-duration` | 요소 | 지연, 재생 시간(ms) |
| `data-morph` | 요소 | 앞뒤 슬라이드에서 같은 값을 가진 요소끼리 위치·크기·색이 이어서 변한다. |
| `data-interact` | 요소 | 상호작용 종류 |
| `data-to` | 요소 | `count-up`의 목표 숫자. 생략하면 요소 글자 속 숫자까지 올라간다. |
| `data-gap` | 요소 | `stagger`의 자식 사이 간격(ms) |
| `data-speed` | 요소 | `typewriter`의 글자 사이 간격(ms) |
| `data-axis` | 요소 | `bar-grow` 방향: `x`(가로) 또는 `y`(세로). 생략하면 모양을 보고 정한다. |
| `data-hidden` | 슬라이드 | 발표할 때 건너뛴다(§3.7). |
| `<aside class="notes">` | 슬라이드 | 발표자 노트. 발표 화면에는 보이지 않는다. |

덱 전체 설정은 `<main id="deck">`에 쓴다: `data-deck-id`(저장소 키), `data-transition`(기본 전환), `data-themes`(예: `"light dark"`, 디자인이 여러 테마를 제공할 때).

**상호작용 요소 쓰는 법**

| 종류 | 마크업 |
|---|---|
| `flip` | 안에 `<div class="front">`(앞면)와 `<div class="back">`(뒷면)을 둔다. 상자에 `height`가 있어야 한다. |
| `reveal` | 내용을 그대로 쓰면 엔진이 가리개를 덮는다. 가리개 글자는 `data-cover-text`로 바꾼다. |
| `quiz` | 보기마다 `data-option`, 정답에 `data-correct`를 붙인다(정답이 여러 개여도 된다). |
| `zoom` | 아무 상자에나 붙인다. |
| `hotspot` | 안에 `<span data-spot data-tip="설명" style="left:30%;top:40%"></span>`을 원하는 만큼 둔다. |

상호작용 요소는 슬라이드에 들어올 때마다 처음 상태(앞면, 가려진 상태, 고르지 않은 상태)로 돌아간다.

### 4.3 모션 라이브러리

새 효과를 추가하면 이 표에도 추가한다. 편집 모드의 모션 선택 목록도 이 표와 같아야 한다.

**슬라이드 전환** (`data-transition`)

| 이름 | 효과 | 잘 어울리는 곳 |
|---|---|---|
| `fade` | 서서히 바뀜 | 설명 슬라이드 (기본값) |
| `slide` | 옆으로 밀려 바뀜 | 이어지는 내용 |
| `push` | 새 장이 이전 장을 밀어냄 | 단계, 과정 |
| `cover` | 새 장이 위로 덮음 | 새 주제 |
| `zoom` | 확대되며 바뀜 | 세부 내용으로 들어갈 때 |
| `flip` | 카드 뒤집듯 회전 | 질문 → 답 |
| `wipe` | 한쪽에서 쓸어내듯 바뀜 | 섹션 전환 |
| `circle` | 가운데서 원이 커지며 열림 | 표지, 섹션 시작 |
| `morph` | 같은 `data-morph` 요소가 위치·크기·색을 이어서 바꿈 | 같은 대상을 확대하거나 재배치해서 설명할 때 |
| `none` | 바로 바뀜 | 빠르게 넘길 때 |

**등장** (`data-anim`)

| 이름 | 효과 | 잘 어울리는 곳 |
|---|---|---|
| `fade` | 서서히 나타남 | 무난한 기본 |
| `fade-up` / `fade-down` / `fade-left` / `fade-right` | 이름의 방향으로 움직이며 나타남 (`fade-up`: 아래에서 위로) | 목록, 문단 |
| `slide-left` / `slide-right` | 이름의 방향으로 크게 밀려 들어옴 (`slide-left`: 오른쪽에서 왼쪽으로) | 비교, 대조 |
| `scale-in` | 작게 시작해서 커짐 | 도형, 카드 |
| `pop` | 툭 튀어나오며 살짝 튕김 | 아이콘, 키워드, 정답 |
| `drop` | 위에서 떨어져 통통 튐 | 재미 요소, 캐릭터 |
| `flip-in` | 3D로 돌며 나타남 | 카드, 사진 |
| `rotate-in` | 회전하며 나타남 | 아이콘 |
| `blur-in` | 흐릿했다가 선명해짐 | 큰 제목, 사진 |
| `wipe` | 가림막이 걷히듯 드러남 | 사진, 도표 |
| `split-words` | 단어가 하나씩 나타남 | 제목, 핵심 문장 |

### 4.4 흥미와 집중을 위한 연출 규칙

- **말하는 순서 = 보이는 순서**: 목록과 도식은 `data-step`으로 하나씩 보여 준다. 설명하기 전에 다 보여 주지 않는다.
- **강조는 한 화면에 한 곳**: 강조 효과는 지금 설명하는 핵심 하나에만 쓴다.
- **동시에 움직이는 것은 최대 2개**: 배경 움직임은 세지 않는다.
- **리듬을 만든다**
  - 표지와 섹션 구분 슬라이드: 크게 (`circle`·`wipe` 전환, 배경 움직임, `split-words` 제목)
  - 설명 슬라이드: 차분하게 (`fade` 계열 등장 + 단계)
  - 핵심 결론: 강조 효과로 못 박기
  - 마지막 슬라이드: 보상 효과로 마무리
- **다양하게, 하지만 일관되게**: 같은 등장 효과를 3장 넘게 연속으로 쓰지 않는다. 섹션마다 전환 효과를 바꾼다. 같은 종류의 내용(예: 모든 퀴즈)에는 같은 효과를 써서 학생이 패턴을 알아보게 한다.
- **집중 리셋**: 대략 슬라이드 5–7장(7–10분)마다 상호작용 슬라이드(퀴즈, 뒤집기 카드, 가리개, 예측 질문)를 하나 넣는다.
- **배경 움직임은 은은하게**: 낮은 채도, 느린 속도로 내용 뒤에 둔다. 글 읽기를 방해하면 뺀다.

### 4.5 동작 규칙

- **앞으로 갈 때만 재생한다.** 뒤로 돌아가면 그 슬라이드는 모든 단계가 끝난 상태로 보여 준다.
- **기다리게 하지 않는다**: 모션이 재생되는 중에 "다음"을 누르면 진행 중인 모션을 즉시 끝내고 다음 단계로 간다. 발표 속도는 발표자가 정한다.
- **시간과 이징 기본값**
  - 슬라이드 전환: 300–700ms
  - 요소 등장: 400–800ms
  - 차례 등장 간격: 60–120ms
  - 기본 이징: `cubic-bezier(0.2, 0.8, 0.2, 1)`
  - 튕김 계열(`pop`, `drop`, `bounce`): `cubic-bezier(0.34, 1.56, 0.64, 1)`
- **모션 강도 설정**
  - `끄기`: 모든 요소가 즉시 최종 상태로 보인다. 상호작용은 클릭하면 바로 결과를 보여 준다.
  - `차분`: 짧은 `fade`만 쓴다. 강조·배경·보상은 끈다.
  - `기본`: 이 문서대로 재생한다.
  - `화려`: 배경 움직임과 보상 효과를 더 크게 쓴다.
  - 기기가 `prefers-reduced-motion`이면 `차분`으로 시작한다.
- **부드럽게**: 모션은 `transform`과 `opacity`로만 만든다(필요하면 `filter`, `clip-path`, SVG `stroke-dashoffset`). 편집 위치는 `left`·`top`·`width`·`height`와 개별 `rotate` 속성에 저장하므로(§6), 모션의 `transform`과 충돌하지 않는다.
- **성능**: 배경 입자는 캔버스 하나로 그린다. 화면에 보이지 않는 슬라이드의 모션과 배경 움직임은 멈춘다.
- **안전**: 1초에 3번 넘게 깜빡이는 효과는 쓰지 않는다(광과민성 발작 예방).
- **효과음은 도구에만**: 슬라이드 모션과 위젯에는 소리를 넣지 않는다. 소리는 타이머 종료와 랜덤 뽑기에만 쓰고, `M`으로 끌 수 있다. 소리는 파일 없이 브라우저에서 만든다(Web Audio).
- **반복 애니메이션은 제한적으로**: 무한 반복은 배경 움직임, `flow`, 상호작용 요소의 "클릭해 보세요" 힌트에만 쓴다. 읽어야 하는 내용에는 쓰지 않는다.
- **내용은 항상 보이게**: 등장 전 숨김 상태는 엔진이 붙인 클래스(`.hz-pre`)로만 적용한다. JS가 실패하거나 모션이 꺼져도 내용은 모두 보여야 한다.
- **인쇄·PDF**: 모든 단계를 펼친 상태로, 한 슬라이드를 한 페이지에 출력한다. 필통·메뉴 같은 엔진 UI는 숨긴다. 뒤집기 카드는 앞면과 뒷면을 나란히 보여 준다.

### 4.6 수업 위젯 (`data-widget`)

여러 강의에서 다시 쓰는 **움직이는 화면 모형**이다. 상자에 `data-widget`을 붙이면 엔진이 구조와 모션을 만든다. 위젯도 단계(`data-step`)와 모션 강도 설정(§4.5)을 그대로 따른다.

| 위젯 | 하는 일 | 마크업 | 등급 |
|---|---|---|---|
| `chapter` | 섹션 시작 화면을 크게 연출한다. 색 띠가 화면을 휩쓸고 지나간 뒤, 큰 번호와 제목 글자가 하나씩 떨어지고, 도형과 색종이 조각이 튀어나온다. | `<div data-widget="chapter" data-part="PART 1" data-num="1" style="left:0;top:0;width:1920px;height:1080px"><h2>제목</h2><p>부제</p></div>` | 권장 |
| `chat` | AI 채팅 화면 모형. 말풍선이 단계마다 하나씩 나오고, AI 답은 ‘입력 중’ 점이 잠깐 보인 뒤 나타난다. 사진·문서를 보낸 말풍선도 쓸 수 있다. | `<div data-widget="chat" data-title="AI 채팅"><p data-from="me" data-step="1">써줘</p><p data-from="ai" data-step="2">물론이죠!</p></div>` · 사진 말풍선은 `data-kind="doc"` | 권장 |
| `autocomplete` | 휴대폰 키보드 추천 단어 모형. 가운데 추천 단어가 차례로 눌리며 문장이 만들어진다. | `<div data-widget="autocomplete" data-step="1" data-words="오늘 학교에서 친구랑" data-pool="그리고 나는 근데"></div>` | 선택 |
| `unlock` | 잠금 카드 묶음. 잠긴 카드가 단계마다 열리며 빛과 조각이 터진다. 이미 얻은 카드는 열린 채로 보인다. 미션을 깰 때마다 보상을 모으는 흐름에 쓴다. | `<div data-widget="unlock"><div data-card data-open>안전장치</div><div data-card data-step="1">디테일</div></div>` | 선택 |

- **모양**: 위젯의 기본 모양은 덱 변수(`--bg`, `--fg`, `--accent`, `--accent-2`)를 따른다. 덱 디자인에서 위젯 안쪽 클래스(`hz-w-` 접두사)를 덮어써 다듬을 수 있다. 엔진 스타일 중 이것만 예외로 허용한다.
- **편집**: 위젯도 상자라서 이동·크기·모션 지정이 된다. 위젯 안 글자는 더블클릭으로 고친다.
- **새 위젯**: 한 강의에서만 쓰는 화면은 그 덱의 디자인과 내용으로 만든다. 두 번째 강의에서도 필요해지면 이 표에 올리고 엔진에 넣는다.

## 5. 디자인: 덱마다 자유

기능(엔진)은 모든 덱이 같고, **디자인은 덱마다 자유롭게** 만든다. 색, 폰트, 배경, 장식, 레이아웃을 덱의 주제와 분위기에 맞게 정한다. 한 덱 안에서 슬라이드마다 레이아웃이 달라도 된다.

### 5.1 디자인을 정하는 방법

- 참고할 디자인(이미지, PPT, 미리캔버스 디자인, 이전 덱)이 있으면 그것을 따른다.
- 없으면 주제와 학생에게 맞게 새로 디자인한다.
- 같은 시리즈(예: 강의 1회차, 2회차)는 디자인을 이어 쓴다.
- 마음에 드는 디자인은 `themes/`에 모아 두고 다른 덱에서 다시 쓸 수 있다. [선택]

### 5.2 어떤 디자인이든 지킬 것

디자인이 아무리 달라도 기능이 똑같이 동작하려면 아래만 지키면 된다.

- **무대**: 16:9, 1920×1080. 필기 좌표와 편집 위치의 기준이다.
- **상자 구조**: 슬라이드 요소는 절대 위치 상자로 배치한다(§6.2). 그래서 어떤 디자인에서도 편집 기능이 똑같이 동작한다.
- **디자인 구역에만 쓰기**: 덱 디자인은 파일의 덱 디자인 구역(§6.1)에만 쓴다. 엔진 스타일을 덮어쓰지 않는다.
- **`.slide` 기준으로 쓰기**: 디자인 선택자는 `.slide`와 클래스로 쓰고 `#deck`은 넣지 않는다. 썸네일, 발표자 보기, 점검은 슬라이드 복제본을 `#deck` 밖에서 그리기 때문이다.
- **색은 CSS 변수로**: `--bg`, `--fg`, `--muted`, `--accent`를 꼭 정의한다(더 필요하면 추가). 엔진은 이 변수를 읽어서 형광펜 강조, 밑줄, 색종이 같은 모션 색과 필통·메뉴의 활성 색을 덱 디자인에 맞춘다.
- **읽히게**
  - 본문은 무대 기준 28px 이상으로 쓴다. 강의실 뒷자리에서도 읽혀야 한다.
  - 강당처럼 청중이 많고 화면이 멀면 본문 44px 이상, 핵심 문구는 더 크게 쓴다.
  - 글자와 배경의 명도 대비는 4.5:1 이상으로 한다.
  - 배경 움직임이나 장식이 글자를 가리지 않게 한다.
- **폰트**: 한글 폰트를 쓴다(웹 폰트는 CDN 허용). 불러오지 못할 때를 대비해 `"Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`를 대체 폰트로 붙인다.
- **레이아웃 등록**: 덱 디자인에 맞는 슬라이드 레이아웃(표지, 섹션 구분, 제목+내용, 퀴즈 등)을 `<template class="hz-layout" data-name="표지">`로 정의해 둔다. 그러면 편집 모드의 "레이아웃으로 추가"(§3.7) 목록에 나온다.
- **라이트·다크**: 디자인이 둘 다 제공하면 `[data-theme="light"]`에서 변수를 다시 정의하고, 설정에서 전환할 수 있게 한다. 하나만 있어도 된다.
- **이미지**: 사용 권한이 있는 이미지만 쓴다.

### 5.3 엔진 UI의 모양

필통, 메뉴 서랍, 편집 도구 같은 엔진 UI는 모든 덱에서 같은 모양이다.

- **종이 패널**: 밝은 종이색 바탕에 진한 남색 글자를 쓰고, 모서리를 크게 둥글린 뒤 부드러운 그림자를 준다. 어두운 덱 위에서도, 밝은 덱 위에서도 잘 보인다.
- **강조색**: 지금 쓰는 도구, 켜진 타일처럼 활성 상태의 색만 덱의 `--accent`를 따른다.
- **아이콘과 이름**: 필통 버튼은 인라인 SVG 아이콘만 보여 주고 이름은 마우스를 올리면 나온다. 메뉴 서랍 타일은 아이콘 아래에 큰 한글 이름을 붙인다.
- **떠 있는 UI는 최소로**: 늘 보이는 것은 메뉴 버튼, 필통, 페이지 꼬리표뿐이다(§2). 새 기능은 기본적으로 메뉴 서랍에 넣는다.

### 6.1 파일 규칙

- **파일 이름**: `YYYY-MM-DD-영문-슬러그.html`. 한글 파일 이름은 zip이나 URL에서 깨질 수 있으므로 피한다. 덱 제목은 파일 안의 `<title>`에 한글로 쓴다.
- **덱 파일 안의 구역 순서**
  1. `<style id="hz-engine-style">` 엔진 스타일: `engine/engine.css`가 그대로 들어간다 (`/* ===== ENGINE vX.Y ===== */` 표시)
  2. `<style id="hz-deck-design">` 덱 디자인: 이 덱의 색, 폰트, 배경, 슬라이드 모양 (`/* ===== DECK DESIGN ===== */` 표시)
  3. `<main id="deck" data-deck-id="..." data-transition="...">`: 슬라이드들과 레이아웃 정의(`<template class="hz-layout">`)
  4. `<script id="hz-engine-script">` 엔진 스크립트: `engine/engine.js`가 그대로 들어간다 (`// ===== ENGINE vX.Y =====` 표시)
- **엔진을 덱 안에 복사해 넣는다**: 단일 파일 원칙(§1) 때문이다. 파일 하나만 보내도 모든 기능이 동작한다.
- **엔진은 `engine/`에서만 고친다.** 덱 안의 엔진 구역을 직접 고치지 않는다. 엔진을 고치면 버전을 올리고, `node tools/sync-engine.mjs`로 모든 덱의 엔진 구역을 바꿔 넣는다. `--check`를 붙이면 바꾸지 않고 최신이 아닌 덱만 알려 준다.
- **엔진은 디자인을 정하지 않는다**
  - 엔진 CSS의 클래스와 id에는 `hz-` 접두사를 붙여 덱 디자인과 겹치지 않게 한다.
  - 슬라이드 안의 글자 크기, 색, 배경 같은 외형은 넣지 않는다.
  - 모션과 상호작용(뒤집기 카드의 회전 등)이 동작하는 데 필요한 최소 스타일만 넣는다.
- **외부 라이브러리 없이** 바닐라 HTML/CSS/JS로 만든다. 폰트 CDN만 예외로 허용한다.
- **이미지는 파일 안에 내장**한다(SVG 인라인 또는 data URI). 파일이 대략 5MB를 넘을 때만 폴더와 `assets/`로 나누고, 폴더째 zip으로 배포한다.
- **브라우저 저장소 키**는 `htmlzip:<data-deck-id>:<항목>` 형식으로 쓴다. 저장소 접근은 항상 `try/catch`로 감싼다. 사파리 개인정보 보호 모드처럼 저장이 막힌 환경에서도 덱은 정상 동작해야 한다.

### 6.2 슬라이드 마크업 규칙 (모든 요소를 편집할 수 있게)

- 슬라이드는 `<section class="slide" data-id="..." data-title="...">`로 쓴다. `data-id`는 덱 안에서 겹치지 않아야 한다.
- 슬라이드의 직계 자식은(발표자 노트 제외) 모두 **상자**다. 파워포인트의 개체처럼, 상자는 무대 좌표 기준 절대 위치를 가진다. `style`에 `left`, `top`, `width`(필요하면 `height`)를 px로 적는다.
- 상자 안에서는 목록, 문단 같은 일반 흐름 레이아웃을 자유롭게 쓴다.
- 편집 모드에서는 다음과 같이 다룬다.
  - 클릭: 상자 선택
  - 더블클릭: 상자 안 글자 수정
  - `Ctrl/⌘ + 클릭`: 상자 안쪽 요소(목록 항목 등) 선택. 모션을 지정할 때 쓴다.
- 편집으로 바꾼 위치와 크기는 `left`·`top`·`width`·`height`에, 회전은 개별 `rotate` 속성에 저장한다. 모션은 `transform`만 쓴다(§4.5).
- 도형은 인라인 SVG로, 이미지는 `<img>`로 넣는다. 둘 다 상자로 다룬다.

### 6.3 영상과 아직 없는 그림

- **영상**: `<video src="assets/파일.mp4" controls>`를 상자로 넣고 폴더형 덱(§6)을 쓴다. 영상 파일이 없으면 엔진이 상자 자리에 “영상 파일을 찾을 수 없어요 · assets/파일.mp4”를 보여 준다. 영상을 클릭해도 다음 슬라이드로 넘어가지 않고, 영상을 조작하는 동안에는 `Space`를 영상에 양보한다. [필수, 영상이 있는 덱]
- **저작권**: 저작권이 있는 영상·그림 파일은 저장소에 올리지 않는다(`.gitignore`). 덱에는 파일 이름과 구하는 방법을 발표자 노트나 README에 적는다.
- **그림 자리표시**: 그림이 아직 없을 때는 `<img src="assets/s01-hero.png" alt="…" data-placeholder="표지 그림: 학생과 AI 로봇">`처럼 쓴다. 파일이 없으면 엔진이 점선 상자에 설명을 보여 주고, 점검에 ‘그림 없음’으로 뜬다. 그림을 넣으면 자리표시는 저절로 사라진다. [권장]

## 7. 완성 체크리스트

덱을 "완성"이라고 하기 전에 아래를 모두 확인한다.

**기본**

- [ ] 크롬·엣지·사파리에서 더블클릭으로 열리고 콘솔 에러가 없다
- [ ] 인터넷 없이 열어도 동작한다 (폰트만 대체됨)
- [ ] 키보드, 버튼, 클릭, 스와이프로 모든 슬라이드를 이동할 수 있고 단계 순서가 맞다
- [ ] 덱의 엔진 구역이 `engine/`의 최신 버전과 같다

**디자인**

- [ ] 어떤 슬라이드 배경 위에서도 필통, 메뉴, 필기, 편집 UI가 잘 보인다
- [ ] 본문이 28px 이상이고 글자 대비가 충분하다
- [ ] 덱 디자인이 덱 디자인 구역 안에만 있고 엔진 스타일을 덮어쓰지 않는다

**필기**

- [ ] 펜, 형광펜, 지우개(획·부분), 레이저, 색, 되돌리기, 이 장 지우기, 전체 지우기가 동작하고, 슬라이드를 넘겨도 필기가 남아 있다
- [ ] 창 크기를 바꾸거나 전체 화면으로 전환해도 필기 위치가 그대로다
- [ ] 칠판과 슬라이드를 오가면 보던 위치로 돌아온다

**전체 화면**

- [ ] 전체 화면에서 슬라이드와 페이지 꼬리표 말고는 아무것도 보이지 않는다
- [ ] 전체 화면에서 가장자리에 마우스를 대거나 탭하면 필통과 메뉴 버튼이 나타났다가 다시 숨는다
- [ ] 전체 화면에서도 이동과 필기 단축키가 동작한다
- [ ] 전체 화면을 끝내면 UI가 돌아온다

**편집**

- [ ] 텍스트, 이미지, 도형을 선택해 이동, 크기 조절, 스타일 변경, 삭제, 복제할 수 있다
- [ ] 요소에 모션을 지정하면 바로 미리보기가 재생된다
- [ ] 슬라이드 순서를 바꾸면 필기도 같이 따라간다
- [ ] 저장한 파일을 다시 열면 모든 수정 내용이 반영되어 있고, 편집용 표시는 남아 있지 않다
- [ ] 점검 결과가 0건이다 (또는 의도한 예외만 남아 있다)

**모션**

- [ ] 연출 규칙(§4.4)을 지킨다: 단계 등장, 섹션마다 다른 전환, 5–7장마다 상호작용 슬라이드, 마지막 장 보상 효과
- [ ] 모션 재생 중에 "다음"을 누르면 즉시 넘어간다
- [ ] 모션 강도 `끄기`와 reduced-motion 환경에서도 모든 내용이 보인다
- [ ] 인쇄 미리보기에서 한 슬라이드가 한 페이지로 나온다

**미디어**

- [ ] 영상이 있으면 파일이 없을 때도 안내가 나오고, 영상을 눌러도 슬라이드가 넘어가지 않는다
- [ ] 저작권이 있는 파일은 저장소에 올라가지 않았다
